# قرار معماري: الانتقال إلى التداول الحقيقي

## الحالة
معتمد للتنفيذ التدريجي.

## الهدف
تحويل التطبيق من نموذج تجريبي إلى منصة تداول حقيقية دون خلط بيانات الاختبار بالتنفيذ المباشر.

## ما تم اعتماده
1. محرك محاكاة متقدم مستقل للاختبارات: انزلاق السعر، زمن الاستجابة، التنفيذ الجزئي، اختلاف السبريد، وتسلسل الأحداث.
2. طبقة حسابات تداول محلية مع تعريف للوسيط ونوع الحساب والخادم ورقم الدخول.
3. كلمات المرور لا تُحفظ كنص مكشوف؛ تستخدم طبقة مخزن مفاتيح أندرويد مع تشفير.
4. حد تنفيذ حقيقي مستقل يدعم مسارين معماريين: واجهة برمجية للوسيط أو جسر منصة التداول.
5. شاشة شموع داخلية مرتبطة بعقد مصدر بيانات السوق الحقيقي، مع جميع الفريمات القياسية دون توليد شموع وهمية.
6. التنفيذ المباشر يبقى مغلقاً حتى تتوفر مصادقة ناجحة، تصريح تنفيذ مباشر، حساب مفعّل، وموصل حقيقي قابل للتحقق.

## حدود السلامة
- لا يتم تحويل وضع التطبيق إلى تنفيذ مباشر بمجرد إدخال بيانات الحساب.
- لا يتم تضمين كلمة مرور أو رمز سري داخل الشيفرة أو المستودع.
- لا يتم افتراض عنوان واجهة برمجية أو بروتوكول وسيط دون مواصفات فعلية.
- ربط منصة التداول يحتاج جسراً فعلياً ومحدداً، وليس مجرد واجهة شكلية.

## الخطوة التالية
تنفيذ موصل حقيقي محدد بعد اختيار مسار الربط: واجهة برمجية فعلية للوسيط أو جسر منصة التداول على الجهاز الذي يشغل منصة التداول، ثم اختبار الاتصال والقراءة أولاً قبل السماح بأي تنفيذ.
