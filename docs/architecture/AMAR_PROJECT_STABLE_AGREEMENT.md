# اتفاق عمار الهندسي الثابت — B1 إلى B36

**الحالة: معتمد وثابت**  
**تاريخ الاعتماد: 2026-09-10**

هذا المستند هو مرجع العمل لهذه المرحلة. أي تنفيذ لاحق يجب أن يحافظ على هذه القرارات ما لم يصدر اعتماد صريح جديد من عمار.

## 1. الدور والمسؤولية

عمار هو صاحب القرار النهائي. المساعد يعمل بصفته المهندس التقني/المعماري للمشروع: يرتب التنفيذ، يفحص الاعتماديات، ينفذ المكونات المعتمدة، يختبرها، ويرفض الادعاء باكتمال أي جزء قبل تحقق شروطه.

## 2. قاعدة التنفيذ

يتم التنفيذ بالتسلسل، جزءًا جزءًا، مع السماح بتقسيم المرحلة إلى دفعات عملية. لا يتم تجاوز طبقة غير مكتملة بصمت إلى المرحلة التالية.

## 3. أولوية المشروع الحالية

الأولوية هي **BOT 1**. لا يتم تشتيت العمل إلى BOTs إضافية أو AI execution قبل تثبيت Runtime وExecution Safety وMT5 integration الخاصة بـBOT 1.

## 4. B34

بناء AMAR BOT RUNTIME PROFESSIONAL LAYER ويتضمن:
- الهوية.
- الحالة.
- الإعدادات.
- Strategy Profiles و10 خانات استراتيجية لـBOT 1.
- Command Lifecycle.
- ACK وVerification.
- Reconciliation.
- Runtime State.
- Position/Pending Order snapshots.
- Telemetry.
- Audit.
- Risk Policy.
- Emergency Lock.
- Simulation/validation boundary.
- Chart synchronization.
- Android ↔ Bridge ↔ MT5 state synchronization.

## 5. B35

ربط BOT 1 الفعلي `Grid_Martingale_Basket_v2` داخل حدود B34. لا يعتبر الربط مكتملًا قبل وجود مصدر MQL5 الأصلي، دمجه، Compile فعلي في MT5، واختبارات السلوك.

## 6. B36

ربط AMAR AI Supervisor كمشرف/محلل وليس كمنفذ مباشر. المسار المعتمد:

AI → Proposal → Decision → Simulation → Risk → Execution Policy → Security → User Approval → MT5

لا يجوز للـAI تجاوز أي طبقة.

## 7. BOT 2–4

تظهر كخانات محفوظة/مهيأة في الواجهة فقط إلى أن يتم اعتماد وتنفيذ Engines مستقلة لها. لا يتم اختراع استراتيجيات تداول حقيقية لها دون اعتماد.

## 8. السلامة

Live execution مقفول افتراضيًا. إدخال بيانات الحساب أو اختيار REAL لا يعني تفويض التنفيذ. أي تنفيذ حقيقي يجب أن يمر عبر المصادقة والصلاحيات والسياسات والأمان والـconnector والـidempotency والـaudit وEmergency Lock.

## 9. الحقيقة التشغيلية

واجهة المستخدم لا تعني أن العملية حدثت. الحالة الحقيقية تأتي من Runtime/MT5 acknowledgment ثم reconciliation. لا يتم إنشاء بيانات سوق أو نسب أو نتائج تداول وهمية.

## 10. الجودة

كل طبقة جديدة يجب أن تكون قابلة للاختبار، قابلة للتوسع، محددة المسؤولية، ومفصولة عن الطبقات غير التابعة لها. التعديلات لا تحذف أو تكسر المكونات القائمة دون ضرورة هندسية واضحة.
