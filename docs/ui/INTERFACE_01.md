# واجهة AMAR AI الرئيسية

الحالة: **مغلقة تصميمياً — بانتظار إثبات CI النهائي للنسخة الحالية**.

## المصدر الفعلي
- `app/src/main/assets/amar_ai_workspace.html` — مصدر العرض الفعلي داخل Android.
- `frontend/app/page.tsx` — المرجع البنيوي للواجهة الجديدة.
- `frontend/app/globals.css` — المرجع البصري.

## القرار المعتمد
هذه هي الواجهة الجديدة المعتمدة لمسار العرض. الواجهة القديمة ذات الدوائر/الاسم المركزي/العناصر المعلقة ليست جزءاً من مسار العرض الحالي.

الواجهة المعتمدة تتكون من:
- شاشة دخول هادئة ونظيفة بدون دوائر معلقة أو شعار مركزي ضخم.
- الرئيسية: مركز الذكاء + بطاقات Agent / Research / Workspace.
- الإيجنت: مساحة محادثة داخلية متصلة بجسر Android إلى مسار AMAR AI.
- البحث، مساحة العمل، الملفات، الذاكرة، والإعدادات كمسارات داخلية واضحة.
- تصميم زجاجي/داكن متجاوب للموبايل، مع حركة بصرية خفيفة فقط دون تشتيت.
- Fail-Closed ظاهر، ولا تمنح طبقة العرض نفسها سلطة تنفيذ.

## مسار الإيجنت
`UI → Android Bridge → AmarAiActionEngine / AmarAiAgentEngine → Result → UI`

الأوامر المحلية التي يثبتها المحرك تمر عبر `AmarAiAppCommandBus`، بينما الإجابات غير المحلية تمر إلى `AmarAiAgentEngine`. لا يوجد مسار مباشر من HTML إلى وسيط التداول.

## اختبارات الإغلاق
قبل إعلان الإغلاق النهائي يجب إثبات:
1. تطابق Android asset مع الواجهة الجديدة المعتمدة وعدم رجوع الواجهة القديمة.
2. فتح الرئيسية والتنقل بين المسارات.
3. فتح الإيجنت وإرسال طلب واستقبال النتيجة عبر الجسر.
4. نجاح اختبارات المحرك وعدم كسر مسار الأوامر.
5. نجاح Gradle build وإنتاج APK قابل للتثبيت.
6. فحص المصدر للتأكد من عدم وجود مسار عرض فعلي للواجهة القديمة.

لا يُستخدم مصطلح "100%" إلا بعد اكتمال هذه الأدلة. اختبار backtest يخص محرك التداول وليس التصميم؛ للواجهة البديل الصحيح هو اختبار مسارات التفاعل والجسر، لا اختلاق backtest بصري.
